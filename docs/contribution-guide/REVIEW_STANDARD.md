# dbexplain Go 项目审查规范

## 审查哲学：一句话原则

**代码是事实，文档是承诺，测试是契约——三者必须自洽。**

```
正确性 > 安全性 > 可维护性 > 性能 > 风格
```

## 九维审查框架

```
┌─────────────────────────────────────────┐
│           外部可见性（用户视角）         │
│  产品定位  ·  友好度  ·  README 匹配    │
├─────────────────────────────────────────┤
│           结构正确性（架构视角）         │
│  架构/文档一致  ·  项目边界  ·  代码规范│
├─────────────────────────────────────────┤
│           运行正确性（工程视角）         │
│  逻辑Bug  ·  并发设计  ·  安全漏洞      │
└─────────────────────────────────────────┘
```

外层（用户视角）→ 中层（架构视角）→ 内层（工程视角），逐层深入。实际审查时建议从内到外执行：先保证代码正确，再检查架构一致性，最后验证对外承诺真实。

## Go 数据库项目专项清单

### A. 资源生命周期

```
必查项：
□ rows.Close()    — 循环内 defer 是函数级，不是迭代级
□ rows.Err()      — Next() 正常结束后必须检查
□ db.Close()      — 连接池超时路径是否覆盖
□ timer.Stop()    — select 成功分支必须 Stop + drain
□ io.ReadCloser   — HTTP body / 文件是否 defer Close()
```

### B. 并发安全

```
必查项：
□ 共享变量        — 有无 race condition（go test -race）
□ channel 方向    — 单向 chan<- / <-chan 是否声明
□ goroutine 泄漏  — 所有 go func() 是否有退出路径
□ context 传播    — 驱动层是否真正响应 ctx.Done()
□ WaitGroup 配对  — Add/Done/Wait 是否 1:1:1
```

### C. 接口与类型安全

```
必查项：
□ interface{} Scan — 断言前检查 ok，避免运行时 panic
□ nil 接口         — 返回 *T(nil) vs interface(nil) 的陷阱
□ 隐式接口实现     — 新增方法后编译器不提示遗漏
□ build tags       — 不同 tag 组合是否都有测试覆盖
```

### D. 错误处理

```
必查项：
□ 错误传播一致性  — log 后忽略 vs 返回，全库统一
□ 错误包装        — fmt.Errorf("%w") 保留链路
□ 错误脱敏        — 任何含 DSN/密码的 error 是否过 SanitizeErr
□ 死代码路径      — err != nil 后的代码是否可达
```

### E. 安全专项（数据库工具必查）

```
必查项：
□ SQL 注入        — 参数化查询，禁止字符串拼接 SQL
□ DSN 密码泄露    — 日志/错误消息必须过 Redacted()
□ 路径遍历        — 文件型数据源用 filepath.Clean
□ 终端注入        — 输出到终端的用户数据需转义
□ 依赖 CVE        — govulncheck ./...
□ 双重编码        — URL 编码在多层传递时是否幂等
```

### F. 文档/代码一致性

```
必查项：
□ 文件名引用      — README 列出的源文件必须实际存在
□ 功能描述        — README 每项功能对应实际可运行代码
□ 废弃标记        — deprecated API 是否有清理计划
□ 测试文档        — docs/test/ 描述与实际测试行为一致
```

## 严重度决策树

```
发现问题时问：

用户数据会丢失或泄露？
  └─ 是 → P0，立即停止合并

功能对外承诺但实际不工作？
  └─ 是 → P1，本次迭代修复

代码正确但未来维护会踩坑？
  └─ 是 → P2，下次迭代

风格/命名/注释问题？
  └─ 是 → P3，技术债积累处理
```

## 验证顺序（每次审查结束必跑）

```bash
# 1. 编译 + 静态分析
go vet ./...
staticcheck ./...          # 死代码、错误用法

# 2. 竞态检测
go test -race -tags full ./...

# 3. 依赖安全
govulncheck ./...

# 4. 覆盖率
go test -tags full -coverprofile=c.out ./...
go tool cover -func=c.out | grep -v "100.0%"

# 5. 构建矩阵（标准版 + full 版）
CGO_ENABLED=0 go build ./cmd/dbexplain/
go build -tags full ./cmd/dbexplain/
```

## dbexplain 项目三条核心审查结论

**优势锚点（守住）：** 单二进制部署 + 接口多态 + DSN 脱敏体系，是产品差异化的技术基础，任何重构不能破坏这三点。

**风险集中区：** `interface{}` Scan 断言、循环内 defer、context 取消传播——Go 数据库代码的三个经典陷阱，此项目均有暴露，需专项回归。

**文档债务：** README/CODE_MAP 引用不存在的文件名是信任破坏点，新贡献者第一天就会踩坑，优先级高于所有 P2 代码问题。
