## 5. 测试理念

### 5.1 项目本质决定了测试方式

`dbexplain` 的核心交付物是一个**零依赖的静态二进制文件**。它不需要 Docker、不需要运行环境、不需要外部进程——扔到任何 Linux/macOS/Windows 机器上就能直接连接数据库并输出报告。

消费方：
- **AI Agent**：通过 `SKILL.md` 调用，消费 stdout 的 Markdown 报告或 `-json` 的结构化输出
- **人类 (DBA/运维)**：直接在终端运行，阅读格式化报告

因此，测试的核心策略应当是：
1. **编译即验证**：`CGO_ENABLED=0 go build` + 交叉编译 5 平台 → 二进制可用
2. **真实数据库直连**：直接跑二进制连接已有的开发/测试数据库实例，而不是用 Docker 模拟
3. **stdout/stderr 正确性**：输出（Markdown 报告或 JSON）是 AI Agent 和人类消费的唯一接口

### 5.2 改进建议

#### 短期 (v0.0.4 计划)

1. **补充单元测试** — 优先为 `dsn.ParseDSN` 和 `filterDSNs` 添加 `*_test.go`，纯逻辑无需外部依赖
2. **接入现有集群验证** — 在有 Redis Cluster / ES HTTPS 的生产或预发环境中，用单次 `-dsn` 命令验证新的 cluster/tls 参数路径
3. **输出格式回归** — 固化一份已知数据集的 JSON/Markdown 输出快照，用于后续 diff 回归

#### 中期 (v0.0.5)

4. **CI 流水线** — GitHub Actions: go build + go vet + go test + 5 平台交叉编译矩阵
5. **DSN 模糊测试** — 用随机 DSN 字符串验证解析器健壮性，防止拼写错误导致 panic
6. **竞态检测** — `go test -race` 验证并发采集部分的 goroutine 安全

#### 长期

7. **真实实例回归** — 在每个 connector 对应的真实数据库上定期跑一遍全量采集，比对报告结构无退化
8. **性能基准** — 对比前后版本的采集耗时，防止大表/大 key 空间扫描逻辑退化
